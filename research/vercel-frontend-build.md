# Vercel Deployment — Frontend Assets Not Building

## Problem

After pushing changes to the `noct/dashboard` branch and triggering a Vercel deploy, the frontend assets (`build/` directory) were not being built. The `dashboard.blade.php` changes (new CSS/JS from the redesign) weren't visible in production.

## Root Cause

The `vercel.json` had an incorrect `@vercel/static-build` configuration:

```json
{
    "src": "/package.json",
    "use": "@vercel/static-build",
    "config": { "distDir": "public" }
}
```

This doesn't actually run `npm run build`. It just copies the `public/` directory as-is without compiling the Vite assets.

## Fix

Updated `vercel.json` to use `installCommand` and `buildCommand` top-level fields:

```json
{
    "version": 2,
    "builds": [
        {
            "src": "api/index.php",
            "use": "vercel-php@0.9.0",
            "config": { "php_version": "8.3" }
        },
        {
            "src": "public/**",
            "use": "@vercel/static"
        }
    ],
    "routes": [
        { "src": "/build/(.*)", "dest": "/public/build/$1" },
        { "src": "/(.*)", "dest": "/api/index.php" }
    ],
    "installCommand": "npm install",
    "buildCommand": "npm run build"
}
```

Key changes:
- Removed the broken `@vercel/static-build` block — replaced with `@vercel/static` for serving `public/` files
- Added `installCommand: "npm install"` — installs dependencies including devDependencies (Vite, Tailwind)
- Added `buildCommand: "npm run build"` — runs `vite build` which compiles `resources/` → `public/build/`
- Vercel automatically runs the build command and deploys the output

## How It Works

1. Vercel clones the repo
2. Runs `installCommand` → `npm install` (installs all deps including vite)
3. Runs `buildCommand` → `npm run build` → `vite build` → generates `public/build/`
4. Serves `public/` via `@vercel/static`
5. All other requests go to `api/index.php` (Laravel)

## The `public/` directory must contain

```
public/
├── index.php          ← Laravel entry point
├── build/             ← Generated by `vite build`
│   ├── assets/
│   │   ├── app-xxxx.js
│   │   └── app-xxxx.css
│   └── manifest.json
└── .htaccess (optional, for Apache)
```

The `build/` directory is gitignored locally (via `.gitignore`) but gets generated during the Vercel build step.

## Local Workflow

```bash
# Build frontend assets
npm run build

# Serve locally with hot-reload
composer run dev

# Serve locally (prod build)
php artisan serve
```

## What to Do After This Fix

1. Push the `vercel.json` fix to the branch
2. Trigger a new deploy on Vercel dashboard (or push a new commit)
3. Vercel will run `npm install` then `npm run build` automatically
4. The new `public/build/` will be included in the deployment

## Alternative: Use Vercel Framework Preset

If using `@vercel/next` or `@vercel/remix` isn't an option, the manual `buildCommand` approach above is correct for Laravel + Vite on Vercel.

## Related Files

- `vercel.json` — deployment config
- `package.json` — `scripts.build` runs `vite build`
- `vite.config.js` — Vite bundler config
- `public/build/` — compiled assets (gitignored, generated on build)
